What messages are passed between mc and fc besides telemetry?

MessagingMissions

Everything between the MC and the FC goes through fcm, over MAVLink. emc doesn't talk to the FC directly; its only MAVLink link is to the FTS. Each message type below is built by a class under services/fcm/fcm/*/mavlink_builders/.

Link heartbeat

  • fcm sends a HEARTBEAT to the FC every 1 s (FC_HEARTBEAT_INTERVAL_MS). When SITL runs faster than real time, the interval shrinks to match.
  • drone_facade streams gRPC heartbeats to fcm. From a launchpad takeoff on, fcm watches them. If they stop, fcm stops heartbeating the FC, starts the fallback mission, and reports a Remote ID system failure (_on_facade_heartbeat_failure).

Mission upload (MAVLink mission protocol)

  • MC → FC: MISSION_CLEAR_ALL, MISSION_COUNT, MISSION_WRITE_PARTIAL_LIST (to extend a mission), then one MISSION_ITEM_INT per item. The item commands used are NAV_TAKEOFF, NAV_WAYPOINT, NAV_LAND, NAV_DELAY, CONDITION_YAW and DO_CHANGE_SPEED.
  • FC → MC: MISSION_REQUEST / MISSION_REQUEST_INT to ask for each item, then MISSION_ACK.
  • During flight the FC sends MISSION_ITEM_REACHED. fcm turns it into waypoint-reached events.

Flight commands (COMMAND_LONG / COMMAND_INT, answered with COMMAND_ACK)

  • COMPONENT_ARM_DISARM: arm, disarm, force disarm.
  • DO_SET_MODE: switch the flight mode. Also used to set the safety switch.
  • MISSION_START, DO_PAUSE_CONTINUE: start a mission, or stop on the path.
  • NAV_LAND: land now.
  • DO_REPOSITION: move in GUIDED, relative or absolute (for example hover at an altitude). SET_POSITION_TARGET_GLOBAL_INT sends GUIDED position targets.
  • DO_CHANGE_SPEED, CONDITION_YAW: set speed and heading.
  • DO_FALLBACK_MISSION: run the fallback mission. This is a Flytrex ArduPilot command, not standard MAVLink.
  • DO_SET_HOME: set home at takeoff.
  • BATTERY_RESET: reset the battery's remaining-capacity count.
  • PREFLIGHT_REBOOT_SHUTDOWN: reboot the FC, or kill it with the magic parameters 42/24/71/94. Kill is a test custom command.

Configuration and identity

  • PARAM_SET / PARAM_REQUEST_READ, answered with PARAM_VALUE. fcm pushes the initial params at startup and after a reboot, and applies set_fc_parameters.
  • SET_MESSAGE_INTERVAL / REQUEST_MESSAGE: set up which telemetry streams the FC sends.
  • REQUEST_AUTOPILOT_CAPABILITIES, answered with AUTOPILOT_VERSION. UAVCAN_GET_NODE_INFO, answered with UAVCAN_NODE_INFO. DO_SEND_BANNER. These give version and hardware ID.

FC logs (Flytrex extension messages)

  • MC → FC: SET_LOG_LABEL (a unique log label per mission), LOG_START_NEW, LOG_REQUEST_LABEL_LIST, LOG_REQUEST_DATA_BY_LABEL, LOG_REQUEST_END.
  • FC → MC: LOG_LABEL and LOG_DATA_EXTENDED, which carry the log download.
  • STATUSTEXT goes both ways. MC → FC writes into the FC log (write_to_fc_log). FC → MC carries ArduPilot text messages.

Remote ID and ADS-B

  • MC → FC: the Open Drone ID messages OPEN_DRONE_ID_BASIC_ID, SELF_ID, SYSTEM, SYSTEM_UPDATE, OPERATOR_ID and ARM_STATUS, from OpenDroneIdCoordinator. OPEN_DRONE_ID_LOCATION also shows up in fcm's ODID code.
  • FC → MC: ADSB_VEHICLE, nearby traffic. fcm checks it for well-clear violations (adsb/).

Not MAVLink but related: fcm also publishes VeerOffPathStatus on RabbitMQ from a periodic geofence-veering check. Test-only custom commands can also fake FC link drops or failed mission uploads.
