Q&A · 2026-11-17

What prompts the version reporting? Is it each module by itself or the software updater?

OTA & firmwareMessagingServices

Each module sends its own version, and only once, when it starts up. software_updater never asks for versions. It just listens, collects them, and sends them to Oversight when it checks for an update.

Who sends what, and when

  • FC, FNU, BMS, PDB, ESC (the CAN devices): sent by fcm as UavcanComponentVersion_* topics on the fcm exchange, when fcm connects to the FC. In ardupilot_fc_commander.py, _request_mavlink_messages_on_initialization asks the FC once (over MAVLink) for AUTOPILOT_VERSION (the FC's own version) and UAVCAN_NODE_INFO (one reply per CAN node). Each reply is converted to protobuf and published as its own topic (UavcanNodeInfoToComponentVersion).
  • FTS: sent by emc as the FtsVersion topic, when emc finishes setting up its devices (initDevicesAndLogic → updateVehicleModuleVersions → publishFtsVersion). The FTS isn't on the CAN bus, so emc is the only process that can read its version.
  • MC (the software): nobody sends it. software_updater reads it itself: it's the image tag of drone_facade in the installed compose file.

What software_updater does

  • Subscribes first. It subscribes to every version topic (FirmwareVersionListener) before it starts the other containers. That matters because the versions are sent only once and aren't replayed; if it subscribed late, it would miss them.
  • Waits for the versions to settle. CAN nodes answer at different times, so it waits at least 60 s, then until no version has changed for 60 s, and never more than 600 s (_are_device_versions_settled in main.py).
  • Reports. It sends the collected list in the update check: [{"module": "fc", "version": ...}, ..., {"module": "mc", ...}].
  • Gets fresh versions after a change. Whenever it restarts the services (after an update, or once when the aircraft is out of service), it clears what it collected. fcm and emc start again and send their versions again.

A separate report to the GCS

emc also sends a version list to Mission Manager, independently of the update flow. In the same startup step, updateVehicleModuleVersions() gathers the fcm versions it has received, plus the FTS and delivery device (VESC) versions, and sends them over the ground link (server.updateVehicleModuleVersions). This also happens only at startup, when emc sets itself up again.
