Q&A · 2026-11-17

Is the code for firmware in this repo or a different one?

OTA & firmwareRepo & tooling

Both, depending on what you mean. The code that installs firmware onto the devices is in this repo. The firmware itself is built somewhere else.

In this repo: the code that installs firmware on the aircraft (the OTA update pipeline)

  • firmware_updater flashes the FC and FTS over USB serial using MAVLink and the ArduPilot bootloader. It asks dronecan_communicator to flash the BMS, FNU and FPC.
  • dronecan_communicator sends firmware files to the CAN devices over DroneCAN (firmware_update_service.py).
  • software_updater downloads the firmware files in a profile, writes firmware_updater's config.yaml, and reads the device versions back off the bus (firmware_manager.py, firmware_versions.py).
  • The add-firmware-device skill walks through adding a new device to this pipeline.

Not in this repo: the device firmware itself

  • The repo has no firmware source code and no firmware binaries (.apj, .bin).
  • The firmware files arrive at update time inside the profile zip that Oversight assigns, and they're flashed as finished builds.
  • The ardupilot_mavlink submodule is only the MAVLink message definitions and the pymavlink library, not ArduPilot firmware.
  • The docs don't say which repos the FC, FTS, BMS, FNU and FPC firmware are built from.

The first install on a fresh board also comes from elsewhere: CLAUDE.md lists a separate emc_controller repo as the installer that copies firmware files and config to the board over SSH.
