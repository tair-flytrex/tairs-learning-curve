In the fcm exchange there are FC telemetry as well as responses from the facade to GCS? Are there any more message types there or is that all?

MessagingArchitecture

No, telemetry and facade responses aren't everything. The fcm exchange is a topic exchange that carries four groups of messages. It's really the shared bus for state between processes: four services publish to it (fcm, drone_facade, emc and software_updater).

1. FC telemetry (published by fcm)

The routing key is the protobuf class name: FcHeartbeat, AerialStateChanged, GlobalPosition, LaunchPosition, AttitudeAndRotationRates, Imu, Barometer, Vibration, GpsRaw, EkfStatusFlags, SystemStatus, ComponentsHealth, TextMessage, WaypointReached, and the per-index BatteryStatus_N, SmartBatteryStatus_N and SmartBatteryInfo_N. Some of these aren't really flight telemetry:

  • UavcanComponentVersion_*: firmware versions for fc, bms1/2, fnu1/2, pdb and esc1..8. software_updater reads these too.
  • OpenDroneIdPublishedMessagePack: Remote ID.
  • FcLogDownloadProgress
  • VeerOffPathStatus
  • AdsbVehicle and AdsbCollision

2. drone_facade state toward emc

FacadeResponseToServer (the replies to ground requests) is only one of these. The others (drone_facade_config.py):

  • UpdateMissionComputerState, UpdateJavaAccordingToFacadeState, UpdateJavaFailureModeAccordingToFacade
  • FacadeStoppedPosition, FacadeTextMessage, FacadeTakeoffProhibitionReason
  • safeUpOriginNodeId, fcLossOriginNodeId, facadeUpdateSafedUpDelay

3. OTA update messages

  • SoftwareUpdateStateChanged: software_updater → drone_facade (IDLE / UPDATING / OUT_OF_SERVICE).
  • FtsVersion: emc → software_updater. This is the only thing emc publishes on this exchange.

4. Other consumers

drone_periph subscribes to AerialStateChanged, for flight-end detection and fan control.
