How do emc and fts communicate?

HardwareMessaging

emc talks to the FTS directly over MAVLink. Nothing goes through fcm, drone_facade, RabbitMQ or gRPC. The FTS is Flytrex's own ArduPilot-based board (accessories/parachute/FlytrexFts.java).

Transport

  • Ioio.newParachuteConnection() (ioio/Ioio.java:42) opens a UART at /dev/mc/serial/fts, 1,500,000 baud (parachute_uart_device, parachute_baud_rate).
  • In SITL it opens a TCP socket instead (parachute_sitl_hostname, port 5762).
  • Devices.java:359 creates FlytrexFts on that connection. FlytrexFts wraps it in MavlinkConnectionWrapper, which uses the dronefleet Java MAVLink library.

Keeping the link alive (MavlinkConnectionWrapper)

  • emc sends a heartbeat to the FTS every 1 s from its own thread. Each heartbeat first waits for LooperIsUnblockedIndicator, which checks that emc's main looper isn't stuck. A hung emc therefore stops sending heartbeats. What the FTS firmware does when they stop is not in this repo.
  • If no FTS heartbeat arrives for 5 s, onHeartbeatTimeout fires and calls onIoError. Read errors, write errors and errors sending a heartbeat also call onIoError.
  • Commands that get no COMMAND_ACK within 200 ms are sent again.

Setup handshake (FlytrexFts.setup())

  • Registers handlers for HEARTBEAT, COMMAND_ACK, SYSTEM_TIME, AUTOPILOT_VERSION, SYS_STATUS, STATUSTEXT and UAVCAN_NODE_INFO. Asks for SYS_STATUS every 1 s and EKF_STATUS_REPORT every 5 s.
  • Sends SYSTEM_TIME, then requests the autopilot version and the banner.
  • Waits up to 5 s for a heartbeat and checks that its type is MAV_TYPE_FTS.
  • Sets FTS_ENABLED=1, LOG_DISARMED=1 and any parachute_params from mc.properties, then waits until each one is acknowledged.
  • Requests the UAVCAN node info, which carries the hardware ID.

emc → FTS

  • MAV_CMD_DO_PARACHUTE enable/disable: arm() / disarm() of the parachute.
  • MAV_CMD_DO_PARACHUTE release: trigger().
  • Arming the FTS itself, buzzer, reboot, start a new log, set params.
  • SET_LOG_LABEL with the mission ID, which starts a new FTS log file, plus STATUSTEXT messages Mission:<id> ID:<vehicle> and Mission ended.

FTS → emc

  • Heartbeat customMode flags: 0x1 enabled, 0x2 healthy, 0x4 triggered. baseMode SAFETY_ARMED means the FTS is ready.
  • When a flag changes, processHeartbeat raises onParachuteArmed, onParachuteDisarmed or onParachuteTriggered. NewMissionLogic listens for these.
  • SYS_STATUS reports pre-arm and sensor health, which the preflight checks use.

Logs

After a flight, emc downloads the FTS .bin log over the same link (mavlink.downloadLog) and uploads it as FTS_LOG. It only does this when fts_log_upload_postflight is set.
