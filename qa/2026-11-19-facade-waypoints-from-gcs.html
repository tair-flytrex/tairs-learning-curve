How does the drone facade receive waypoints from the GCS (in what structure)?

MessagingMissions

The waypoints arrive as the GCS's own JSON, unchanged. emc only wraps it. drone_facade parses the JSON and converts it to its own protobuf mission items.

1. GCS → emc

Mission Manager sends JSON-RPC requests over a WebSocket. Waypoints come in set_flight_plan, update_flight_plan (an extension) and set_rtl_flight_plan. set_mission carries the mission id, the takeoff_node (launch point) and config (safe-up altitude and timeout, pickup from launchpad).

2. emc → facade (server/MissionServer.java:684)

emc puts every request into a gRPC ServerMessage (drone_facade.proto:47) and calls report_server_message:

  • message_type: the JSON-RPC method, e.g. "set_flight_plan".
  • payload: the JSON-RPC params as UTF-8 JSON bytes, unchanged.
  • request_id: the JSON-RPC id, so the facade's reply can be matched.
  • is_downlink: true for messages from the ground.

3. The JSON shape (the fields the converter reads)

  • flight_plan_id, an optional dock_parameters (position, yaw_heading, altitude_msl, height_agl) and is_dock_takeoff.
  • flight_legs[]. Each leg has:
    • nodes[]: each node has an id, a point {lat, lng, ca_m (cruise altitude, MSL), ge_m (ground elevation, MSL)} and an optional safe_up_path[] of points.
    • simplified_node_indexes[]: which nodes are turn points. The first and last nodes always are.
    • post_action: pickup, dropoff, landing or dock_landing.

4. JSON → protobuf (drone_facade/old_api_message_converters/server_message_converter.py)

ServerMessageHandlers (server_handlers.py) queues the message. ServerMessageConverter._convert_message runs json.loads on the payload and picks a converter by message_type:

  • set_mission → SetGcsMissionRequest.
  • set_flight_plan → SetGcsMissionItemsRequest, which includes a takeoff.
  • update_flight_plan → ExtendGcsMissionItemsRequest, with no takeoff.

_convert_flight_legs_to_mission_items builds a list of GcsMissionItems:

  • A TakeoffManeuver first, with launchpad, post-ascend and cruising-altitude waypoints taken from the first node.
  • For each leg, a WaypointMission item. Each node becomes an ExecutableWaypoint: lat/lng, altitude MSL = ca_m, ground altitude = ge_m, uid = the node id, and is_turn from simplified_node_indexes.
  • Each waypoint also gets descent, fallback and safed-up strategies, and a path_to_safe_point made from safe_up_path (or the node itself if there is none).
  • Then a maneuver item for the leg's post_action: pickup, dropoff, land, or dock enter.

The converter also maps each protobuf waypoint uid back to the GCS node id (waypoint_uid_to_flight_path_node_id_converter.py), so progress reports to the ground use the GCS's node ids. Finally, _call_drone_service_with_server_message passes the request to the mission executor. When it flies a leg, the WaypointMission is sent to fcm, which turns it into MAVLink.
